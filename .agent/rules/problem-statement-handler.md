# Multi-Domain Analysis & Approval-Gated Execution Protocol

Whenever the user provides a hackathon problem statement, theme, or idea, DO NOT modify files or write code yet. Follow this strict 2-stage gate:

## STAGE 1: Multi-Domain Tech Scan & Plan Proposal (NO FILE EDITS)
1. **Cross-Domain Technology Evaluation**:
   - Evaluate the problem across ALL relevant fields: **AI & Agentic Workflows** (LangGraph, MCP, Agentic RAG), **Machine Learning & Data Science** (Polars, DuckDB, predictive modeling, multimodal vision/audio), **Cloud & Edge Computing** (Serverless, Docker, Workers AI, Supabase), **Cybersecurity & Guardrails** (PII redaction, NeMo Guardrails, zero-trust auth), and **Modern Full-Stack** (FastAPI, Next.js, real-time SSE).
   - Select the highest-ROI trending technologies that fit a 24-hour build.
2. **Present the Master Plan**:
   - **Winning Angle**: Why this solution beats generic hackathon projects.
   - **System Architecture**: How data flows from frontend to backend, AI/ML/Data pipelines, and cloud services.
   - **24-Hour MVP Roadmap**: Concrete breakdown of Phase 1 to Demo.
3. **Mandatory Approval Gate**:
   - Stop immediately after presenting the plan and ask: **"Do you accept this plan, or would you like to swap any tech/features?"**

## STAGE 2: Execution (ONLY AFTER USER ACCEPTS)
Once the user replies with "Accepted", "Yes", or approves the plan:
1. Update .gsd/PROJECT.md, .gsd/REQUIREMENTS.md, .gsd/ROADMAP.md, and progress.txt with the approved architecture and tasks.
2. Output the **"What To Do Now"** step-by-step checklist and begin Phase 1 via the Ralph Loop.
